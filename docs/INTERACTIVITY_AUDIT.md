# 전 학년 교구 인터랙션·교과 타당성 점검

> 상태: 2026-11-23 / 자동 테스트와 수학교구 연결 검증. **교사 검수 완료가 아닙니다.**

## 점검 원칙

학생에게 '터치 가능'이라고 표시했으면 그 **그림 자체가 실제로 조작되어야** 합니다. 버튼이 존재하는 것만으로는 합격 처리하지 않습니다.

1. **직접 조작:** 도형·개별 단위·사탕·구슬·그래프 위에 마우스를 올리거나 터치하면 무엇을 선택하는지 명확해야 하고 실제로 변화해야 합니다.
2. **수학적 보존·관계:** 화면의 변화가 수량·식·단위·면의 연결 등 실제 원리에 대응해야 합니다. 예시의 숫자와 화면의 그림 수를 일치시킵니다.
3. **원리를 이해시키는 진행:** 결과값을 바로 보여 주기 전에 원인과 중간 단계를 조작하고 확인할 수 있어야 합니다.
4. **터치·키보드·반응형:** 데스크톱, 태블릿, 모바일에서 조작하고 문제·정답 보기는 한 화면에 들어가야 합니다.
5. **자동 테스트 분리:** (A) 83개 주제 렌더링·조작 컨트롤 유무, (B) 지정 교구 수학적 불변량, (C) 실제 마우스 드래그, (D) 모바일 화면, (E) 전문가 수업 검수는 **각기 다른 등급**입니다.

### 학습 유형 전체 회귀 검증

- `tests/all-topics-render.test.tsx`: 기존 **83개 수학 주제를 하나씩 모두 렌더링**하고 조작 가능한 요소가 최소 하나 있는지 검사
- 121개 성취기준 각각이 실제 83개 문제·교구 주제와 매핑되어 있는지 검사
- 기존 `tests/labs.test.tsx`, `tests/standard-subskills.test.mjs`, `tests/standard-studio.test.tsx`와 함께 실행
- 모바일 360×640 / 390×844, 태블릿 768×1024, 데스크톱 등 브라우저 시험은 해당 주제별 Playwright 테스트로 확인

**주의:** 83개 렌더링 테스트는 모든 주제에 충분한 직접 조작과 교육적 설명이 있다는 것을 증명하지 않습니다. 별도 교구 테스트가 확인한 기능까지만 통과로 기록합니다.

## 아직 교과 품질 점검이 필요한 영역

코드가 구동하는 것과 실제로 어린이가 원리를 학습할 수 있는 것은 다릅니다. 다음 내용은 **아직 전체 교과 검수를 끝내지 않았습니다.**

- 혼합 계산·소수 나눗셈: 연산 순서와 소수점 이동을 교구 내부에서 실제 한 단계씩 보여 주는지
- 비례 배분: 색깔 구슬 비율만 보여 주는 데 그치지 않고 전체 수량을 실제 몫으로 나누는지
- 분수 나눗셈: 막대의 크기 비교가 아닌 ‘몇 번 들어가는가’를 정확히 시각화하는지
- 경우의 수와 가능성: 시행 결과의 불규칙성과 이론적 가능성의 차이를 혼동하지 않는지
- 121개 성취기준의 학습 목표: 하나의 자동 문제 생성 엔진을 여러 성취기준에 공유하기 때문에 **모든 하위 지식·기능·태도를 독립 평가했다고 단언할 수 없음**
- 저학년의 읽기 난이도·난독/시각 접근성, 모바일 실제 기기 사용성, 교사에 의한 문제·해설·성취기준 교차 검수

## 완료 판단 기준

**통과:** 주제별 화면 렌더링, 위 표의 신규 교구별 핵심 수학 계산과 실제 조작 테스트, 모바일에서 문제와 선택지 표시.

**미완료:** 121개 교육과정 전체에 대한 교육전문가 검수, 모든 주제의 교수법·난이도 검증, 실제 학습자의 조작·이해도 평가.

사용자가 단원마다 오류를 발견하는 방식은 개발 품질관리 방법으로 사용하지 않습니다. 새로 추가하는 교구는 먼저 수학 모델 테스트·실제 학생 조작 테스트·브라우저 화면 테스트를 갖추도록 하며, 문제 없는 것과 추가 검수가 필요한 것을 구분해 보고합니다.
